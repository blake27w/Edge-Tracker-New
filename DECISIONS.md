# Edge Tracker — Decisions

Append-only. Newest at the bottom. Format: `D<n> (YYYY-MM-DD) — decision — why`.

- D1 (2026-07-05) — `~/Edge-Tracker-New` is the canonical repo; `~/edge-tracker/` and Desktop copies are archived — it's the GitHub-synced tree with the latest work (PR #120, 2026-07-03).
- D2 (2026-09-16) — Learning-loop bundle landed as direct commits to `main`, not a PR — Blake asked for push-to-main explicitly; CLAUDE.md's branch/PR norm still stands for future work.
- D3 (2026-09-16) — `scripts/migrate-research.sql` lives in the repo rather than only in the delivery zip — the schema the new agents depend on should be reconstructible from the tree alone.
- D4 (2026-09-16) — History agents read closing lines from ESPN's **core** API (`sports.core.api.espn.com/.../competitions/<id>/odds`) when `site.api`'s `pickcenter` is empty, and skip any provider whose name matches `/live/i` — ESPN empties pickcenter for older games (the key stays, the array goes to `[]`), which is why nfl-history graded only 124 of 588; the "Live Odds" entries are in-game snapshots that would poison totals (ORE/MSU 2024: 52.5 close vs 39.5 live).
- D5 (2026-09-16) — History agents distinguish "no line on record" from "fetch failed", and never cache a failed fetch — a transient error used to poison that game for the life of the process.
- D6 (2026-09-16) — Football gets priority Sep–Jan via **two** mechanisms, both keyed off `FOOTBALL_PRIORITY=auto|true|false` (auto = Sep–Jan, evaluated per call so a long-running process crosses months): (1) NFL/NCAAF stay in the per-sport **ceiling** denominator all season even with no slate on the board; (2) their unspent credits form a **floor** non-football sports may not spend into — the allocation shares are ceilings and spend is sequential, so a share alone never protected football. In Sep 2026 MLB+soccer drained the 20k by day 15 while NFL had used 1064 of ~7450. The two are not redundant: ceilings stop other sports *earning* an inflated share (football's 0.48 leaving the denominator inflated soccer's cap to ~2040 vs ~700), the floor stops them *spending* football's remainder.
- D7 (2026-09-16) — Odds budget is the real constraint, not agent coverage: 19915/20000 used by day 15 (pace ×1.99), which is why ~30 agents reported "no games on the slate". Fixes above take effect at the Oct 1 reset; `ODDS_SKIP_SPORTS=SOCCER,WNBA,BOXING` alone is only ~12% of spend and was never going to close a 2× overrun.
- D17 (2026-10-14) — `book-move` derives per-book movement from **`line_snapshots`**, not from the pre-computed per-book movement table — that table's baseline is a process-local Map, so every redeploy wipes it and the first fetch of each key detects nothing; a lead/follow percentage over rows whose existence depends on deploy timing looks authoritative and is not. Snapshots are written unconditionally every run and carry `last_update`, the book's own "when I changed my number" stamp, which is what makes lead/follow measurable *below* our fetch cadence. Bounded as one query per game × market keyed on `game_id` (rides `line_snapshots_game_idx`), slate capped at 24 games, `side` filtered in JS so the index prefix stays a full equality match — no new index on the largest table.
- D18 (2026-10-14) — Public attribution is **market-wide only**, and labelled as such in the payload, the agent header and the PWA explainer — `public_splits` has no `book` column, so a per-book public split is not derivable from our data and the agent must not imply one. Equally, the lead metric is **not** proof of sharp action: our book list is 11 licensed US retail books with no originating book among them, so "led the field" measures who copies the true market fastest. Outside NHL/NBA/MLB/NFL `public_pct`/`vs_public` are `null` and the score loses that component — the remaining weights are renormalized so a missing input is neutral, not a penalty; the UI says "no public data" rather than implying consensus.
- D19 (2026-10-14) — Book reputation (`market-maker` / `follower` / `mixed`) is **derived** from the trailing 14 days of `book_move_log`, never hardcoded — our book list changes, no retail book deserves a maker prior, and a baked-in table would silently go stale where a derived one self-corrects and is auditable. Bootstrap cost accepted: `role` is noise for ~2 weeks, which the `small` flag (n < 20) discloses, and the `lead` score component falls back to 0.5 until a book has a sample.
- D20 (2026-10-14) — Episode importance weights (0.30 magnitude / 0.20 key-number / 0.15 early / 0.20 vs-public / 0.15 lead) and `MIN_SCORE=35` are judgement, not measurement — they sit in one `W` object plus `BOOK_MOVE_MIN_SCORE` so they can be retuned in a single place once there is a graded sample. `early` deliberately rewards distance from kickoff (a bias toward origination: late steam is also sharp but is hardest to separate from public volume). Key numbers moved to `agents/shared/key-numbers.js` so `key-number` and `book-move` cannot drift apart. Ships observational only — these episodes do not feed plays.
- D21 (2026-10-17) — The line-movement work pivoted mid-session from generalizing open→close movement to **per-book attribution**, because Blake's actual question ("which books move in which ways, and which are hit by sharps vs the public") cannot be answered by the open→close design: that reads live *consensus*, a cross-book median, which collapses exactly the per-book detail the question needs. The generalization spec is kept at `docs/specs/line-move-all-sports.md` as the next phase. No new Odds API spend either way — movement detection was already per-book (`odds/index.js:236` keys on `${game}|${book}|${market}|${side}`) and `line_movements` already had a `book` column; the gap was never capture, only that nothing read it.
- D22 (2026-10-17) — Two ceilings on this signal are inherent to the data and are stated in the payload rather than papered over: (1) `public_splits` has no `book` column, so "hit by the public" is market-wide only and a true per-book public split is not derivable; (2) the book list is 11 licensed US retail books with no originating book (no Pinnacle/Circa/exchange), so "led the field" measures which retail book copies the true market fastest, not who sharps bet with. Closing (2) means adding an originating book to the odds feed, which costs API spend — a separate decision, deliberately not taken here.
- D23 (2026-10-17) — `rankLevels` groups arrivals by **line level + direction**, not level alone — two books converging on -3.5 from opposite sides (one drifting -3 → -3.5, one -4 → -3.5) are not participating in the same market move, so ranking them against each other credited whichever arrived first with a lead it never earned and inflated `led_pct` on choppy markets. Blake's call after the shipped version was flagged as ranking level-only. Guarded by a smoke assertion verified to fail when the grouping key is reverted; the 97-case behavioral suite confirms the genuine-lead, tie, lone-book and revisited-level cases are unchanged.
