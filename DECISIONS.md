# Edge Tracker — Decisions

Append-only. Newest at the bottom. Format: `D<n> (YYYY-MM-DD) — decision — why`.

- D1 (2026-07-05) — `~/Edge-Tracker-New` is the canonical repo; `~/edge-tracker/` and Desktop copies are archived — it's the GitHub-synced tree with the latest work (PR #120, 2026-07-03).
- D2 (2026-09-16) — Learning-loop bundle landed as direct commits to `main`, not a PR — Blake asked for push-to-main explicitly; CLAUDE.md's branch/PR norm still stands for future work.
- D3 (2026-09-16) — `scripts/migrate-research.sql` lives in the repo rather than only in the delivery zip — the schema the new agents depend on should be reconstructible from the tree alone.
- D4 (2026-09-16) — History agents read closing lines from ESPN's **core** API (`sports.core.api.espn.com/.../competitions/<id>/odds`) when `site.api`'s `pickcenter` is empty, and skip any provider whose name matches `/live/i` — ESPN empties pickcenter for older games (the key stays, the array goes to `[]`), which is why nfl-history graded only 124 of 588; the "Live Odds" entries are in-game snapshots that would poison totals (ORE/MSU 2024: 52.5 close vs 39.5 live).
- D5 (2026-09-16) — History agents distinguish "no line on record" from "fetch failed", and never cache a failed fetch — a transient error used to poison that game for the life of the process.
- D6 (2026-09-16) — Football gets priority Sep–Jan via **two** mechanisms, both keyed off `FOOTBALL_PRIORITY=auto|true|false` (auto = Sep–Jan, evaluated per call so a long-running process crosses months): (1) NFL/NCAAF stay in the per-sport **ceiling** denominator all season even with no slate on the board; (2) their unspent credits form a **floor** non-football sports may not spend into — the allocation shares are ceilings and spend is sequential, so a share alone never protected football. In Sep 2026 MLB+soccer drained the 20k by day 15 while NFL had used 1064 of ~7450. The two are not redundant: ceilings stop other sports *earning* an inflated share (football's 0.48 leaving the denominator inflated soccer's cap to ~2040 vs ~700), the floor stops them *spending* football's remainder.
- D7 (2026-09-16) — Odds budget is the real constraint, not agent coverage: 19915/20000 used by day 15 (pace ×1.99), which is why ~30 agents reported "no games on the slate". Fixes above take effect at the Oct 1 reset; `ODDS_SKIP_SPORTS=SOCCER,WNBA,BOXING` alone is only ~12% of spend and was never going to close a 2× overrun.
- D8 (2026-10-14) — Edge Tracker owns its own `.claude/` agent + skill definitions, adapted from Pool Room Pro's rather than copied — `/feature` invoked here was resolving to PRP's copy and the two had diverged, with Edge Tracker holding the *stale* side (its `feature` still spawned the retired verifier agent). Ported the lessons, not the files: `wrap` now pushes a branch and surfaces a PR per CLAUDE.md, deliberately not PRP's `git push origin main`, and `kickoff` keeps no pull-guard — that invariant exists for PRP's two-machine Blake/Brad sync, which this repo does not have.
- D9 (2026-10-14) — The PWA's information architecture moves from sport-first to function-first: sport becomes a FILTER, not a navigation level — two competing nav axes (a home launcher plus 12 per-sport modules) meant the same ~6 concepts were reimplemented per sport across 94 render functions (Stats 5×, Log 4×, Dash 4×, Hist 3×).
- D10 (2026-10-14) — Phase 1 consolidates **Games** first and lands strictly alongside the old launcher, removing nothing — 10 of 12 sports have a games tab and `renderGamesBoard`/`renderGamesHTML` are already sport-parameterized off one endpoint, making this a navigation wrapper rather than a renderer merge, and the path is read-only so a defect cannot corrupt logged bets. Rejected Log first (writes 9 localStorage arrays — a defect loses bets) and Dashboard first (entangled with single-slot global model state that needs keying by sport first).
- D11 (2026-10-14) — Phase 1 specifics, decided by Blake: a 7th launcher tile is **added** rather than replacing the "Sports" tile (additive = cleanly revertible); the sport filter **shares `state.sport`/`et_sport`** rather than introducing `state.gamesSport` (duplicating the "current sport" concept is the exact doubling this project exists to remove); and **all 10 chips always show**, with the existing empty-state note explaining off-season sports, rather than hiding chips on an empty fetch.
- D12 (2026-10-14) — The verifier agent is retired in this repo too, and the reviewer is kept — the verifier's runaway-loop cost is not worth it and Blake is the verifier of record, but with one 7700-line file and no test suite there is no safety net to catch a regression, so one adversarial review round earns its keep. It found 5 confirmed defects, all in the new fetch/cache layer, including one that would have blanked a loaded board.
- D13 (2026-10-14) — `tools/smoke.mjs` is the repo's first automated check, bootstrapped because `index.html` is one ~7700-line statically-served file where a syntax error silently breaks everything and the only prior safety net was a human opening the page. It pins the reviewer's confirmed defects as regressions so Phase 2 cannot quietly reintroduce them.
- D14 (2026-10-14) — The API's CORS allowlist admits local dev origins (anchored `localhost`/`127.0.0.1`/`[::1]`) — a browser on localhost could otherwise never reach the backend, so the PWA was only testable once deployed and no local verification loop could exist. Not a widening: the existing rule already admits any `*.vercel.app` subdomain, which anyone can register, and every POST/DELETE is gated by `authed()` independently of CORS.
- D15 (2026-10-14) — `projectedMonthly` in `/budget` is not a decision input and the odds tier stays put — it linearly extrapolates `perDay` while ignoring the per-sport ceilings, and `capOf()`'s 0.85 factor caps total spend near 17000 by construction. Four sports were already hard-capped on day 14 (matching the agent's own `4 budget-skips`), so October lands near 18114, under budget. The real constraint is allocation **shape**: NCAAF starved at its seasonal peak, which a bigger tier would not fix because the ceiling is a share.
- D16 (2026-10-14) — Line-movement tracking is recorded but not learned from, and fixing it is the next feature: `line_movements` is write-only (the sole reference in the codebase is its INSERT), the live consumers read only the most recent odds run's in-memory array, the detection baseline is process-local so every redeploy blinds it, and open→close tracking is NFL-only despite `opening_lines` being written sport-agnostically. Order: generalize `nfl-line-move` to all sports, then give `line_movements` a reader, then persist the baseline.
