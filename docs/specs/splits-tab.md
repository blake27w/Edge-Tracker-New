# Splits tab — public bets % / handle % against open → current lines

Status: proposed · 2026-11-06 · branch `feat/splits-report` off `5b92d70` (= `origin/main`) · next decision **D101** · **amended 2026-11-06: per-book line switcher** (lines and movement switch by book; percentages never do — per-book splits are a sourcing decision, Follow-up 1)

## Problem

Blake wants one place on his phone to read public splits the way the BetMGM *Sportsbook Data Insights* sheet presents them: per game, Spread / Total / ML, opening line → current line, % bets and % handle on both sides, so his eye can find money-vs-tickets divergence and reverse line movement — and to **click between books** and see each book's lines. The data already exists in three places that nothing joins — `public_splits` rows (percentages + `rlm`/`freeze`/`pileon`/`net_move`, with `line_open`/`line_current` always `null`), `opening_lines`, and the in-memory slate's consensus — and the only reader today is a 13th chip on the Plays tab (`renderSplitsBoard`, `index.html:8166`) that shows percentages with no lines. The feed is also empty right now (`public-splits` is `blocked` — key set, no credits, `/data-health` reads `public_splits: 0 today`), so the tab's first job is to say that honestly rather than paint a blank table.

## Approach

**A ninth home tab, `splits` ("📊 Splits"), registered at the same seven anchors as the Signal tab (#138), painting under `.sighud` so it reads as part of the same instrument.** Not a sixth Signal panel: Signal's panels are system instruments (health, budget, books, steam, close) and its `.sh-nav` is already five chips in a 4-column grid; a per-game card list with its own sport selector is a different shape and Blake asked for "a tab". The existing Plays → 📊 Splits chip stays but its renderer becomes a one-line delegate to the new body so the two cannot drift (the `sigEpisodeCard` pattern, D83).

**The join happens in the server route, not the PWA.** `/splits` already walks the slate and derives per-book lines; it gains `open`/`current` per game and `splits_meta`. Openers come from the `nfl-line-move` store slot, which already reads `opening_lines` for every slate game each run (chunked, D95) — the agent additionally publishes its `openMap` as `openers[game_id] = {total, spread, ml}` so started games are covered too (its `live[]` drops them). Current lines are `computeMarkets(g)` consensus (home spread, Over total, home ML), live and free. Rejected: reading `opening_lines` inside `/splits` (the route is polled every 30 s by `startAgentsPoll`; `/games` already does an unchunked `in:` read per request and that is a precedent to stop, not copy); the odds agent's in-memory `openings` Map (post-restart it records the *current* line as the opener — D75 notes it is never pruned for the same reason); joining in the PWA from `/plays.lineMove.live` (excludes started games, and ties a 90-min-cadence payload to a 4-hour one).

**Durability: a bounded DB fallback inside the route, used only when memory is empty.** After a Railway restart `getIntel('splits')` is `[]` until the next 4-hour run while the last batch sits in Postgres. When memory is empty, the DB is connected, and an in-process cache is older than `SPLITS_DB_TTL_MS` (10 min), the route runs **one** select: `public_splits`, newest `SPLITS_DB_LIMIT = 300` rows by `fetched_at desc` (rides `public_splits_fetched_idx`; a batch is ≤ 60 rows, so this is ~5 batches), then in JS keeps each game's newest `fetched_at` and drops games not on the slate (counted, not hidden). The result and its timestamp are cached; a failed read caches the failure for the same TTL so a timing-out table is not hammered 120×/hour. Memory wins whenever it has rows. `splits_meta.source` says which path produced the rows (`memory` / `db` / `null`) and the PWA shows it.

**Phone-first card per game; the sheet's 16-column grid is not reproduced.** Sport chips at the top (`All · NBA · NFL · NHL · MLB`, the `SPLIT_SPORTS` set, restated once as a literal), cards sorted by tip-off. Card: sport tag + tip-off (or LIVE), away over home stacked, then three compact mono rows — SPREAD / TOTAL / ML — each showing `open → now` (home-side spread, Over total, home ML; `—` when either is unknown) and a two-sided `bets% · handle%` readout ordered away/home or over/under. The split row stores one side (the public side); the other side is `100 − pct`, computed only when the pct is non-null and labelled as the complement in the footer. The side whose `handle − bets ≥ 5` is emphasised in mint (never both; none when `|divergence| < 5` or either pct is null). Flags render as small chips per row: `RLM` (wine), `FREEZE` (brass), `PILE-ON` (dim); `rlm === null && freeze === null` on a lopsided row renders the words `no line data`, `net_move == null` renders `—`. A `<details>` disclosure at the card foot holds the existing per-book table (markup moved from `renderSplitsBoard`, inside `.sigtbl-wrap`) — the only thing that scrolls sideways, and only inside its own box. Wide screens (`min-width:700px`) lay the same cards in a 2-column auto-fill grid (`.sh-eps` already does this); a denser table was rejected because it needs a second renderer for the same data.

**Book switcher (amendment): a second chip row under the sport chips — `Consensus` (default, today's behaviour) plus every book present on the filtered slate, labelled from `BOOK_LABELS` (`config/index.js:149`, the table `odds/index.js:95` imports).** Selecting a book changes exactly two things on every card: the **lines** in the three rows and the **movement chips**. It never changes a percentage. The split from `public_splits` has no `book` column (D53, the renumbered D18; D22), the percentages are Claude-read and market-wide, and no per-book count is captured anywhere in this system — so a selected book's card carries a one-line label above the rows: *`splits are market-wide — <Label>'s own counts are not captured`*. Per-book **current** needs no new work: `/splits.games[].books[]` already carries each book's `spread_line` / `total_line` / `ml_home` from `g.books[bk].markets` (`buildSplits`, `src/index.js:279-290`); it gains a stable `key` (`bk`, the Odds API key) because `book` there is the display label and the join to `bookMoves` is by key. Per-book **opener** is **the book's first `line_snapshots` row on file for that game × market**, derived inside the `book-move` agent and published on its slot as `openers[game_id][book] = {spread, total, ml}` — a value is `null` when that book has no row, never `0`, never the consensus opener. Rendered as `open (first seen) → now`; `—` for the opener when null, with the book's current still shown. Why `book-move`: it is already the per-book movement reader of `line_snapshots`, already on the same `(game_id, market)` equality prefix of `line_snapshots_game_idx` (D52; applied — D70 lists it among the three that are in), already caps its slate at `MAX_GAMES = 24` in `[now−3h, now+24h]`, and its 15-min cadence means a game gets its opener within one run of entering the window. **Bound:** one select per game × market, `match: {game_id, market}`, `order fetched_at asc` (a backward scan of the desc index; no `gte`, no `in:`), `limit OPEN_BOOK_LIMIT = 40` (one batch is ≤ 22 rows: 11 books × 2 sides — 40 covers the first batch and slop, and the first batch is the only one that matters), over `OPEN_MARKETS = ['spreads','totals','h2h']` (the fixed `±1.5` run line is still a number; h2h is included because the ML row needs an opener even though `MARKETS` excludes it from scoring), **memoised per `game_id` for the process lifetime** so steady-state cost is new games only (≤ 72 selects on a cold run, then ~0; an opener never changes — the D75 property), evicted at kickoff + 6h (D75's cutoff). A failed read is counted in the summary and retried next run; it never writes a memo. Rejected: deriving in the `/splits` route (30-s poll × 3 selects × N games against the table that statement-timeouts, D68); in `nfl-line-move` (its header says it deliberately does not read `line_snapshots`, and 3 × ~300 slate games every 90 min is 4× the cost for no better coverage); `bookMoves.live[].line_from` (it is the *from* of a move that scored ≥ `MIN_SCORE`, top 40 only — most book × market pairs have no episode, so the opener would be absent exactly where the line was quiet); showing the consensus opener next to a per-book current (one arrow, two sources, reads as a per-book move that was not observed — the "silently substituted" case the test plan forbids). **Movement chips** for the selected book are that book's episodes from `bookMoves.live[]` (`book`, `game_id`, `market`, `led`, `lead_rank`, `crossed_key`, `moved`, `score` — already in the bag via `/plays`) joined by `game_id` + `book` + market (`spreads`→SPREAD, `totals`→TOTAL; `book-move` scores no h2h, so the ML row shows none): `led field` / `led by N`, `crossed 3`, `−2 move` — the agent's `reasons[]` strings, rendered as chips. Consensus shows none (they are per-book by nature) and no label. Per-book coverage is `book-move`'s 24-game window: a game outside it shows `open —` and no chips, and the chip row's `<small>` count is the number of games with a per-book opener so the gap is visible. The chip row scrolls horizontally inside its own `.sp-books` container (`overflow-x:auto` on that box only); the card grid is unchanged. Selection persists in `localStorage` under `et_splitsBook` via raw `try{localStorage.setItem(...)}catch(e){}` — **not** `save()` (`:629`), which also queues a cloud sync — read once at init, defaulting to `consensus`, and reset to `consensus` if the stored key is not on the current slate.

**Zero new fetches.** `loadAgentsData()` (`index.html:6155`) already fetches `/splits`, `/plays` and `/health` into the bag, `applyAgentsBag` already writes `state.agentsSplitsBoard` (6122), `state.agentsBookMoves` (6129) and `state.agentsHealth`/`state.agentsSystem`, and `sigSrc.splits` already records the read outcome (6203). The tab reads only those. Every field access is defaulted — an `etBagCache` replay from before this change has no `open`, `current`, `splits_meta`, `books[].key` or `bookMoves.openers`, and must paint the percentages it has with `open —` rather than throw; with no `books[].key` the book row shows `Consensus` alone.

**Five honest states via `sigBanner`, with `off` naming the real cause.** State resolution (`splitsFacts()`), in this order:

| state | when | copy |
|---|---|---|
| `failed` | `state.sigSrc.splits.ok === false` | `sigBanner('failed', sigFailOpts('/splits', …))` — banner over whatever is cached |
| `loading` | `state.agentsSplitsBoard == null` and `sigSrc.splits.at` unset | `sigBanner('loading')` |
| `off` | the `public-splits` entry in `state.agentsHealth` has a non-null `blockedReason`, **or** `state.agentsSystem.degraded` contains `key === 'public-splits\|blocked'` (the 90-min TTL channel; the health field is the durable one, D80) | `sigBanner('off', {text: 'NOT FIRING — public-splits is blocked: "' + blockedReason + '" (' + blockedRuns + ' runs since ' + since + '). Percentages are blank because the agent cannot run, not because the public is quiet. Lines below still update.'})` plus a `.sh-cap`: `A set key with no model detected at boot is what an account with no credits looks like from here: add credits, then redeploy once — the model probe runs only at boot (D81).` The cap shows only when the reason matches `/no model was detected/`. |
| `stale` | newest `splits_meta.at` older than `SPLITS_BOUND = AGENT_STALE_MS['public-splits'] * 2` (8 h) | `sigBanner('stale', {ago, bound: '8h (2× the 4-hour public-splits cadence)'})` — over the data |
| `nodata` | source ok, not blocked, zero split rows for the selected sport | `sigBanner('nodata', {things: 'public-split rows for this slate', at})`; if `splits_meta.at` exists, a cap `last batch <ago> ago, none for the current slate` |

Inside the bound the strip reads `batch <ago> · every 4h` in plain mono — 4 hours is the design, not an alarm. `splits_meta.source === 'db'` adds `restored from Postgres after a restart`. A card whose game has lines but no split rows shows the three rows with `—` for every percentage and `no split for this game` once — never a `0%`. The book selection does not enter state resolution: the five states are about the percentages, which do not vary by book.

**What the tab says about itself (fixed footer):** `Source: public-splits agent — Claude web search over sportsbettingdime / DK Network / Covers / VSiN. Market-wide consensus; no per-book splits exist (D53/D22). The second side of each pair is 100 − the reported side. Per-book openers are the first line on file for that book (book-move, nearest 24 games). Divergence is a reading, not a pick.`

## Data model / API changes

No DDL. No new table columns (D96: the same `rows` array is inserted into `public_splits`, so nothing is added to the row). **One new localStorage key**, `et_splitsBook` (string, default `consensus`).

1. **`nfl-line-move` store slot gains `openers`** (`edge-tracker-agents/src/agents/nfl-line-move/index.js:271`): `openers: Object.fromEntries(games.map(g => [g.game_id, {total: r1(openMap.get(id+'|total') ?? null), spread: …, ml: openMap.get(id+'|ml') ?? null}]))` — every slate game, started or not; a missing opener is `null`, never 0. ≤ ~300 entries. `setNflLineMove(null)` paths are unchanged (no slot → no openers → `open: null`).

2. **`/splits` payload** (additive; old cached clients keep working):
   ```
   { count, games: [{ game_id, sport, matchup, home, away, commence_time, live,
       open:    {total, spread, ml} | null,     // consensus opener; null when line-move has not published it
       current: {total, spread, ml},            // computeMarkets consensus now; each may be null
       splits: [{ market, side, public_side, bets_pct, handle_pct, divergence, rlm, freeze, pileon, net_move, fetched_at }],
       books: [{ key, book, updated, ml_home, ml_away, spread_line, spread_price, total_line, over_price, under_price }] }],
     splits_meta: { source: 'memory'|'db'|null, at: <newest fetched_at>|null, rows: N, offslate: M, db_error: bool } }
   ```
   `books[].key` is the Odds API book key (`bk` in the loop); `book` stays the label. `public_side` ∈ `home|away|over|under|null`, from the agent's `resolveSide(g, market, side)` (exported, unchanged). `open`, `current` and every pct are passed through raw — `null` stays `null` (D96/D97), no `Number()` on a possibly-absent value (house rule). **The `splits[]` rows carry no `book` field, by design.**

3. **`bookMoves` slot gains `openers`** (`setBookMoves`, `book-move/index.js:466`): `openers: { [game_id]: { [book]: { spread: n|null, total: n|null, ml: n|null } } }` for the games in this run's slate plus memoised ones still inside kickoff + 6h; `openers_meta: { games: N, selects: K, failures: F, limit: OPEN_BOOK_LIMIT }`. Canonical sides as elsewhere: home spread, Over total, home ML price. A book absent from the first batch is absent from the object (reads as `undefined` → `—`), never `0`.

4. **`buildSplits` moves to `src/games/splits.js`** and becomes `async buildSplits(url, deps = {})` so it can be driven by `node:test` with `fakeDb` (`src/index.js` calls `main()` on import, `:489`, so nothing in it is importable). Route call at `src/index.js:442` becomes `await buildSplits(url)`.

## Risks & open questions

1. **Launcher shape.** `.launch-grid` is 2 columns (`:59`); nine tiles leaves one orphan cell. Options: accept it, or let the ninth span both columns (`.launch-btn:last-child:nth-child(odd){grid-column:1/-1}`). Blake's call; the spec assumes accept.
2. **The decisive check needs credits + a redeploy.** Until then every card shows lines with `—` percentages under the `off` banner. That is the correct output and the reason the banner exists; do not pad it.
3. **`openers` lags new games by one `nfl-line-move` run (90 min).** A game that joins the slate between runs shows `open —` until then. Honest; a per-request DB read was rejected above.
4. **A DB-restored batch can be hours old and partially off-slate.** `splits_meta.at` and `offslate` make that visible; the `stale` banner fires past 8 h. The PWA never mixes a DB row with a memory row because the route never returns both.
5. **Only one side per row is observed.** The complement is arithmetic on a two-way market and is labelled as such; if a future source reports both sides, drop the derivation rather than reconcile it.
6. **Per-book coverage is 24 games, −3h..+24h (book-move's cap).** On a Saturday most games have no per-book opener and no chips until they are among the 24 nearest; the chip count discloses it. Raising `BOOK_MOVE_MAX_GAMES` is an env change and a `line_snapshots` load decision, not this spec's.
7. **"First seen" is not "the book's opener".** A book that posts a week out is first seen when the game enters the odds agent's 36-h horizon — the same semantics `opening_lines` already has (D75: first-seen consensus), so the two openers are comparable, but the row header says `(first seen)` rather than `open` to keep the claim exact. Snapshot retention is unknown here; if the earliest row has been purged, "first on file" is still what is shown.
8. **Per-book opener is lost on restart until the next `book-move` run (≤15 min)** — `—` meanwhile, like every other in-memory slot.
9. **Not claimed:** per-book splits (none exist, D53/D22 — and the card says so in words whenever a book is selected), any "sharp" verdict beyond the ≥5-point emphasis and `book-move`'s own `reasons`, `line_open`/`line_current` on the row (left `null`; a backfill is a separate decision), ML movement chips (`book-move` scores no h2h).
